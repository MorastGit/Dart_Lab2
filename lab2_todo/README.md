# Lab2 ToDo 

Консольное приложение для управления списком задач, написанное на Dart. Задачи можно добавлять, просматривать, отмечать выполненными и удалять. Вывод раскрашен с помощью пакета `ansicolor`.

- **Имя:** Козубенко Елена  
- **Группа:** ИСП-241  

## Запуск

1. Клонировать репозиторий: `git clone <url>`
2. Перейти в папку: `cd lab2_todo`
3. Установить зависимости: `dart pub get`
4. Запустить: `dart run`

## Команды приложения

| Команда  | Описание                    |
|----------|-----------------------------|
| `add`    | добавить задачу             |
| `list`   | показать все задачи         |
| `done`   | отметить задачу выполненной |
| `delete` | удалить задачу              |
| `exit`   | выйти                       |

## Что изучили

- Создание классов в Dart: поля, конструкторы (в том числе краткая запись `this.title` и именованные параметры с `required`) и методы.
- Переопределение метода `toString()` с помощью `@override` для удобного текстового представления объекта.
- Геттеры (`get status`) и статические поля (`static int _counter`) для автоматической генерации ID.
- Ввод с клавиатуры через `stdin.readLineSync()`, работа с `String?` и безопасное преобразование строки в число через `int.tryParse()`.
- Подключение пакетов с pub.dev (`dart pub add`), файлы `pubspec.yaml` и `pubspec.lock`, каскадный оператор `..`.

## Ответы на вопросы

**1. В чём разница между полем класса и обычной переменной в функции?**

Поле класса объявляется в теле класса и принадлежит объекту у каждого экземпляра свой набор полей и доступны всем его методам. Обычная переменная в функции существует только во время выполнения этой функции и после её завершения исчезает.

**2. Что такое конструктор и зачем он нужен?**

Конструктор это специальный метод, который вызывается при создании объекта. В Dart он называется как класс. Он нужен, чтобы инициализировать поля объекта начальными значениями (в Dart с null-safety все поля должны быть инициализированы), а также чтобы задать какие данные необходимо передать при создании объекта.

**3. Зачем нужен `@override` перед `toString()`? Что будет, если его убрать?**

`@override` сообщает компилятору, что метод переопределяет метод родительского класса. Если убрать `@override`, код всё равно будет работать, так как метод с именем `toString()` переопределится в любом случае, но мы потеряем эту защиту: при опечатке (например, `tostring()`) ошибки не будет, а `print(task)` выведет `Instance of 'Todo'`.

**4. Чем статическое поле `static int _counter` отличается от обычного поля? Сколько копий этого поля существует в программе?**

Обычное поле принадлежит каждому объекту отдельно сколько объектов создано, столько и копий поля. Статическое поле принадлежит классу целиком и существует в единственном экземпляре, общем для всех объектов. Поэтому `_counter` существует в программе в одной копии независимо от количества созданных задач

**5. Что означает нижнее подчёркивание в `_counter`?**

делает идентификатор приватным. В Dart это работает на уровне файла, а не класса: к `_counter` нельзя обратиться из других файлов, но код внутри того же файла `todo.dart` имеет к нему доступ.
